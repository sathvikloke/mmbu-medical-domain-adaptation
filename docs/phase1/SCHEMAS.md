# Phase 1 schema contract

**Status:** binding field-level design contract; executable validators remain unimplemented  
**Frozen:** 2026-10-14  
**Scope:** governance and evidence records only; official task/context output keys remain behind a versioned prompt/schema adapter

## Common rules

Every JSON object below is UTF-8 without BOM, rejects duplicate keys and nonfinite numbers, and rejects unknown keys unless a field explicitly contains an open metadata object. Schema IDs use the exact `mmbu.phase1.<name>` strings below and `schema_version` is integer `1`. Timestamps are RFC 3339 UTC strings ending in `Z`; chronology compares parsed instants, never lexical local time. Digests are lowercase 64-character SHA-256 hex over the named canonical domain.

Canonical JSON is RFC 8785. A `record_digest` is SHA-256 of the canonical object with only its top-level `record_digest` field omitted. No other field is omitted. File digests cover raw bytes. IDs are opaque nonempty strings and never substitute for digests.

Exact evaluator-derived rationals use only the closed reduced `{"denominator":D,"numerator":N}` object defined by `EVALUATOR_MECHANICS.md`; a JSON decimal, string fraction, unreduced object, negative denominator, boolean integer, or alternate zero is invalid wherever that wire type is required.

Normalized repository and evidence paths are nonempty relative POSIX paths: no leading slash, backslash, empty component, `.`, `..`, NUL, Unicode-normalization alias, case-fold collision, symlink, hard-link alias, or directory entry. Arrays are ordered unless stated otherwise. Set-like arrays are unique and sorted by UTF-8 bytes before canonicalization.

The canonical enums are:

- purpose: `engineering`, `quarantine_inspection`, `train`, `adaptive_dev`, `confirmation`, `official_audit`, `release`;
- origin: `mmbu_official`, `mmbu_derivative`, `official_rule_summary`, `external_reviewed`, `external_quarantine`, `synthetic_engineering`, `unknown`;
- claim status: `verified`, `failed`, `untested`, `blocked_external`;
- contract status: `synthetic`, `brief_snapshot`, `organizer_confirmed`;
- edge role: `governance`, `data`, `model`, `prompt`, `processor`, `judge`, `decision`;
- decision kind: `candidate_admission`, `experiment_priority`, `hyperparameter_choice`, `seed_choice`, `prompt_choice`, `checkpoint_selection`, `promotion`, `release`;
- phase decision: `accepted`, `returned_blocked`, `rejected`.

`null` is allowed only where explicitly named. Missing and null are not interchangeable.

## `mmbu.phase1.lineage_receipt`

Required fields:

| Field | Type | Rule |
|---|---|---|
| `schema_id`, `schema_version` | string, integer | Exact common values. |
| `lineage_id` | string | Unique opaque ID. |
| `artifact_digest` | digest | Child artifact raw-byte or canonical-record digest. |
| `origin_class` | origin enum | `unknown` fails promotable purposes. |
| `allowed_purposes` | array of purpose enum | Unique sorted array; empty is legal and denies use. |
| `parents` | array of object | Each object has exactly `parent_digest` and `edge_role`; unique pair, sorted by digest then role. |
| `source_version`, `rights_receipt_digest`, `grouping_receipt_digest`, `qa_receipt_digest` | digest or null | Non-null for `external_reviewed` in real model-use purposes. |
| `created_at` | UTC timestamp | Receipt creation. |
| `record_digest` | digest | Canonical record digest. |

The effective allowed-purpose set is the intersection of the child declaration and every content-bearing ancestor reached through `data`, `model`, `prompt`, `processor`, `judge`, or `decision` edges. A pure `governance` edge is excluded only when its target validates as `official_rule_summary`; relabeling content or decisions as governance fails. Cycles, missing parents, an `unknown` ancestor, public/derivative ancestry in a promotable purpose, or an empty intersection reject use.

For an `official_rule_summary`, the lineage receipt must have exactly one direct `governance` parent and a matching `mmbu.phase1.sanitized_rule_extraction` receipt whose `output_digest` equals `artifact_digest`. For a decision payload, the complete direct-parent digest set must equal both the decision plan's full `allowed_input_digests` and the decision-execution receipt's full `mounted_input_digests`; each `official_rule_summary` parent uses `governance` and every other decision-content parent uses `decision`. A subset, extra parent, or wrong edge role is invalid even if its surviving ancestry is otherwise clean.

## `mmbu.phase1.sanitized_rule_extraction`

Required fields: `schema_id`, `schema_version`, `extraction_id`, `source_digest`, `source_origin_class`, `source_span_registry_digest`, `included_spans`, `excluded_content_classes`, `extraction_function_digest`, `output_digest`, `reviewer_attestations`, `created_at`, and `record_digest`.

`source_origin_class` is exactly `mmbu_official`. `included_spans` is a nonempty unique source-location-sorted array of closed objects with exactly `source_locator`, `start`, `end`, and `extracted_bytes_digest`; locations and byte boundaries are explicit and nonoverlapping. `excluded_content_classes` is the complete sorted set `example_id`, `image`, `question`, `answer`, `label`, `annotation`, `benchmark_outcome`, `example_statistic`, `error_analysis`, and `example_derived_recommendation`. `reviewer_attestations` contains exactly two closed objects with distinct nonempty `reviewer_id`, `reviewed_output_digest` equal to `output_digest`, `disposition` equal to `approved` or `rejected`, `reviewed_at`, and `attestation_digest`; both must be `approved`. The extraction function accepts only the declared spans and emits only normalized rule text plus source locators. Missing spans, changing output bytes after review, a reviewer collision, any protected-content class, or a summary that ranks a model or development choice invalidates the receipt.

## `mmbu.phase1.decision_plan`

Required fields: `schema_id`, `schema_version`, `plan_id`, `decision_kind`, `purpose`, `scope`, `subject_ids`, `allowed_input_digests`, `forbidden_origin_classes`, `forbidden_root_digests`, `decision_function_digest`, `command_digest`, `source_state_digest`, `sandbox_policy_digest`, `planned_opening_event`, `operator_id`, `created_at`, and `record_digest`.

`subject_ids` and `allowed_input_digests` are nonempty unique sorted arrays. Except for the closed candidate-admission exception below, every allowed input resolves before `created_at` to a complete valid lineage graph whose effective purposes include `purpose`; none may have origin `mmbu_official`, `mmbu_derivative`, `unknown`, or a forbidden root for a promotable purpose. A `candidate_admission` plan has purpose exactly `quarantine_inspection`; its sole subject is one candidate/quarantined source, and it may read only that source's exact artifact manifest, proposed-purpose set, rights, grouping, QA, custody summary when applicable, and their attestations/lineage. Those preapproval inputs may have empty or quarantine-only effective purposes solely for admission review; this exception grants no proposed model-use purpose and cannot authorize an experiment. `forbidden_origin_classes` is exactly the sorted set `mmbu_derivative`, `mmbu_official`, and `unknown` for every promotable decision. `forbidden_root_digests` includes every known suspended/quarantined decision root in the bound authority registry. The plan predates `planned_opening_event`; changing a subject, input, rule, command, source state, or sandbox policy creates a new plan and cannot bless already opened results.

## `mmbu.phase1.decision_payload`

Required fields: `schema_id`, `schema_version`, `decision_id`, `plan_digest`, `decision_kind`, `purpose`, `subject_ids`, `selected_subject_ids`, `dispositions`, `claim_digests`, `rationale_digest`, `created_at`, and `record_digest`.

The plan digest, decision kind, purpose, and subject IDs match the plan byte-for-byte. `selected_subject_ids` is a unique sorted subset of `subject_ids`; `dispositions` contains exactly one closed object for every subject with `subject_id`, `status`, and `reason_code`, sorted by subject ID. Status is `selected`, `not_selected`, `blocked`, or `ineligible`. `claim_digests` is a nonempty unique sorted array and every claim resolves to an allowlisted input or a deterministic derivative produced inside the same decision execution. Free-form rationale is a separate immutable artifact bound by `rationale_digest`; the payload cannot include hidden observations or replace missing evidence with narrative.

## `mmbu.phase1.decision_execution_receipt`

Required fields: `schema_id`, `schema_version`, `receipt_id`, `plan_digest`, `decision_payload_digest`, `rationale_digest`, `output_lineage_receipt_digest`, `source_state_digest`, `command_digest`, `sandbox_policy_digest`, `mounted_input_digests`, `observed_content_read_digests`, `emitted_output_digests`, `attempted_denied_reads`, `network_events`, `operator_attestation`, `independent_review`, `started_at`, `ended_at`, `exit_code`, `terminal_status`, and `record_digest`.

The plan exists before `started_at`; its command, source state, and sandbox policy match. `mounted_input_digests` equals the plan's complete `allowed_input_digests`, and `observed_content_read_digests` is a duplicate-free subset recorded by the sandbox. `emitted_output_digests` is exactly the sorted pair consisting of `decision_payload_digest` and `rationale_digest`. `attempted_denied_reads` and `network_events` are empty; the sandbox is network-denied, mounts only allowlisted content read-only, and begins with an empty writable output directory. The output lineage receipt's artifact is `decision_payload_digest`, its origin is the inherited clean origin or `external_reviewed`, and its complete direct-parent digest set equals `mounted_input_digests`; official rule summaries use `governance`, every other decision-content parent uses `decision`, and no other direct parent is allowed. `operator_attestation` is a closed object with `operator_id`, `no_undeclared_influence`, `no_protected_memory_used`, `attested_at`, and `attestation_digest`; both booleans must be true. `independent_review` is a closed object with a distinct `reviewer_id`, `reviewed_plan_digest`, `reviewed_payload_digest`, `reviewed_rationale_digest`, `disposition`, `reviewed_at`, and `attestation_digest`; all digests match and disposition is `approved`. Success requires exit code zero, terminal status `succeeded`, and `ended_at >= started_at`. Manual payloads, mismatched output, unlogged mounts, extra reads, denied-read attempts, network activity, self-review, missing content parents, or late plans are ineligible for experiment binding.

## Real-source admission evidence

A digest in a source or authorization record is valid only when it resolves to the named closed schema, its canonical `record_digest`, and a member of the bound evidence manifest.

### `mmbu.phase1.reviewer_attestation`

Required fields: `schema_id`, `schema_version`, `attestation_id`, `payload`, `payload_digest`, `verification`, and `record_digest`.

`payload` is a closed object containing exactly `statement_version`, `reviewer_id`, `reviewer_role`, `subject_digest`, `purposes`, `disposition`, `limitations_digest`, `reviewed_at`, and `declaration_text_digest`. `statement_version` is exactly `mmbu-review-attestation-v1`; `purposes` is a nonempty unique sorted array of purpose enums; `disposition` is `approved`, `rejected`, or `blocked_external`. `reviewer_role` is exactly one of `acquisition_reviewer`, `rights_reviewer`, `grouping_reviewer`, `clinical_qa_reviewer`, `visual_qa_reviewer`, `adjudicator`, `candidate_admission_reviewer`, `purpose_authorization_reviewer`, `release_reviewer`, or `custody_reviewer`. `payload_digest` is SHA-256 of the RFC 8785 canonical payload. `verification` is a closed object containing exactly `method`, `verifier_id`, `verified_at`, and `verification_artifact_digest`; method is `manual_identity_check` or `cryptographic_signature`. This record proves a verified immutable declaration, not cryptographic identity unless the latter method and its independently verifiable artifact are present.

The subject digest names the exact bytes reviewed. Rights, clinical/visual QA, candidate-admission, final purpose, and release decisions require distinct attestations even when one qualified person fills multiple roles. Automated analysis may support review but cannot supply a named human rights, credential, prize-eligibility, clinical, or release disposition required by the contract.

For a record with one `reviewer_attestation_digest`, its attestation subject is SHA-256 of the RFC 8785 canonical object with only `record_digest` and `reviewer_attestation_digest` omitted. For a QA or custody record, omit only `record_digest` and `reviewer_attestation_digests`. For a source approval, omit only `record_digest` and `approval_attestation_digest`; for model lineage, omit only `record_digest` and `completeness_attestation_digest`. No other field is omitted. The final record digest still follows the common rule and therefore binds the attestation digest. Where a reviewed record also carries `reviewer_id`, it equals the attestation payload's reviewer ID.

### `mmbu.phase1.source_artifact_manifest`

Required fields: `schema_id`, `schema_version`, `manifest_id`, `source_id`, `source_version`, `source_family`, `canonical_locator_ids`, `acquisition_authorization_digest`, `acquisition_execution_receipt_digest`, `artifacts`, `total_bytes`, `retriever_id`, `retrieved_at`, `retrieval_log_digest`, and `record_digest`.

`canonical_locator_ids` is a nonempty unique sorted array. `artifacts` is a nonempty path-sorted array of closed objects containing exactly `logical_path`, `bytes`, `sha256`, `upstream_checksum`, `media_type`, and `role`. Paths obey the common normalized-path rule; bytes are nonnegative integers; SHA-256 covers exact local bytes. `upstream_checksum` is null or a closed object with `algorithm` equal to `md5`, `sha1`, `sha256`, or `sha512` and lowercase hexadecimal `value`. `role` is `archive`, `metadata`, `annotation`, `image`, or `terms`. The acquisition receipt succeeded under the named acquisition authorization while it was the active unexpired registry head; source identity/version/family, operator, destination, artifact basenames, byte counts, and SHA-256s equal the receipt exactly, while canonical locators equal the referenced authorization. `retriever_id`, `retrieved_at`, and `retrieval_log_digest` equal the receipt's operator, end time, and log digest. No path, digest, or source identity may change after creation; a changed upstream release or local byte creates a new source lineage, not a transition. The summed artifact bytes equal `total_bytes`.

### `mmbu.phase1.acquisition_authorization`

Required fields: `schema_id`, `schema_version`, `authorization_id`, `source_id`, `source_version`, `source_family`, `canonical_locator_ids`, `identity_evidence_digests`, `terms_digest`, `allowed_artifact_names`, `intended_purpose`, `staging_destination`, `retrieval_method_digest`, `retrieval_command_digest`, `operator_id`, `network_host_allowlist`, `maximum_bytes`, `decision`, `inspection_prohibited`, `reviewer_attestation_digest`, `authorized_at`, `expires_at`, `supersedes_digest`, and `record_digest`.

`allowed_artifact_names` and `network_host_allowlist` are nonempty unique sorted sets derived from the reviewed official identity; names are exact normalized basenames, never globs. `intended_purpose` is exactly `quarantine_inspection`; `maximum_bytes` is a positive integer; `decision` is `allowed`, `denied`, or `blocked_external`; `inspection_prohibited` is true. An allowed, unexpired authorization permits the named operator and exact command/method only to transport allowlisted artifacts into the normalized sealed staging destination plus stream byte counts, hashes, and inventory needed to construct `mmbu.phase1.source_artifact_manifest`. Decompression, rendering, decoding, content parsing, label/statistic inspection, model access, and developer access remain forbidden until the resulting manifest, quarantined source, container-level quarantine split, quarantine-inspection purpose authorization, registry head, prospective inventory lock, and protected-access opening receipt all validate. The approved acquisition-reviewer attestation binds the authorization subject. A first record has null `supersedes_digest`; a successor preserves source identity/version/family, binds the active predecessor, and becomes the sole head at `authorized_at`. Denial, blocking, expiry, or supersession revokes staging authority without editing history. Retrieval exceeding the byte cap, touching an unlisted host/name, changing command/operator, or producing bytes inconsistent with reviewed identity evidence fails closed and requires a successor authorization.

### `mmbu.phase1.acquisition_execution_receipt`

The retrieval log is immutable evidence of transport, byte counting, hashing, and inventory only.

### `mmbu.phase1.qa_sampling_plan`

Method is `simple_random`, `stratified`, `clustered`, `stratified_clustered`, or `census`; required N is positive and confidence is finite in `(0,1)`. `sampling_function_digest` identifies exact immutable code/specification including PRNG family/version, canonical population order, seed derivation, independent-unit sampling, record expansion, stratum allocation, tie behavior, and output serialization. `seed_material_digest` binds the exact seed bytes, not a language-dependent integer interpretation. `strata` is a nonempty stratum-ID-sorted array of closed objects containing exactly `stratum_id`, `definition_digest`, `eligible_units`, and `planned_review_units`; every count is positive, planned units do not exceed eligible units, and their sum equals `required_n`. `thresholds` uses exactly the closed prospective-lock threshold shape. Its unique IDs contain one overall critical-error rule, exactly one critical-error rule for each stratum, and exactly one rule for every required shortcut probe; every rule binds the metric, estimand, finite value, unit, direction, and underpowered disposition. `multiplicity_rule` uses exactly the prospective-lock shape and its hypothesis IDs equal all decision-bearing QA threshold IDs; `approval_function_digest` identifies exact immutable code/specification that maps frozen observations, thresholds, multiplicity, completeness, and adjudication into every receipt disposition. The plan is created after the inventory opening and population manifest but before the QA lock and opening. The QA prospective lock has phase `custody_qa`, its `qa_sampling_plan_digest` equals this plan, its input artifacts include this exact plan and population, its `seed_ids` is exactly the singleton `seed_material_digest`, its `thresholds` and `multiplicity_rule` equal the plan byte-for-byte, and its `decision_function_digest` equals `approval_function_digest`. Its groups are the exact stratum-sorted projection with `group_id=stratum_id`, matching `definition_digest`, `parent_unit=independent_unit_namespace`, `minimum_parents=planned_review_units`, `role=multiplicity_family`, and `underpowered_disposition=block`. The QA opening receipt's protected manifest set contains both plan and population digests. Any mismatch or backdated/rewritten plan invalidates QA.

### `mmbu.phase1.qa_receipt`

Required fields: `schema_id`, `schema_version`, `receipt_id`, `source_artifact_manifest_digest`, `eligible_population_manifest_digest`, `qa_sampling_plan_digest`, `purposes`, `converter_digest`, `target_schema_digest`, `eligible_record_manifest_digest`, `source_annex_digest`, `sample_independent_unit_ids_digest`, `sample_ids_digest`, `error_counts`, `overall_threshold_id`, `critical_error_upper_bound`, `critical_error_ceiling`, `strata_results`, `adjudication`, `annotation_completeness`, `shortcut_results`, `approval_function_digest`, `reviewer_attestation_digests`, `disposition`, `limitations_digest`, `reviewed_at`, and `record_digest`.

`purposes` is a nonempty unique sorted array and equals the bound QA plan's complete proposed-purpose set. The eligible population, both sample digests, purposes, converter, independent-unit namespace, strata, and reviewed-unit counts equal the referenced immutable population and plan; `reviewed_at` is after the QA opening. `error_counts` is a closed object containing nonnegative integer `critical`, `major`, `minor`, and `reviewed_independent_units`. Bounds and ceilings are finite numbers in `[0,1]`. For approval, reviewed independent units equal the plan's `required_n`, with no extra or missing sampled unit or expanded record. `overall_threshold_id` resolves the plan's sole overall critical-error threshold, `critical_error_ceiling` equals its frozen value, and the upper-bound disposition is recomputed by the frozen approval function.

`strata_results` is a nonempty stratum-ID-sorted array of closed objects containing exactly `stratum_id`, `threshold_id`, `eligible_units`, `reviewed_units`, `critical`, `major`, `minor`, `critical_upper_bound`, `critical_ceiling`, and `disposition`. It is the exact plan-stratum projection: IDs and eligible units match, each threshold ID resolves that stratum's frozen rule, every ceiling equals its frozen value, and approval requires `reviewed_units=planned_review_units`; disposition is recomputed as `pass`, `fail`, or `underpowered`. `adjudication` is a closed object containing exactly `disagreement_count`, `disagreement_manifest_digest`, `adjudicated_count`, `adjudicator_attestation_digest`, and `unresolved_count`; counts are nonnegative and approval requires unresolved count zero. `annotation_completeness` is a nonempty target-ID-sorted array of closed objects containing exactly `target_id`, `eligible_units`, `annotated_units`, `not_annotated_units`, `negative_units`, `negative_rule_digest`, and `disposition`; counts are nonnegative, statuses exhaust eligible units, `not_annotated` never counts as negative, and disposition is `pass`, `fail`, or `blocked_external`. `shortcut_results` is a nonempty probe-kind-sorted array of closed objects containing exactly `probe_kind`, `threshold_id`, `input_manifest_digest`, `method_digest`, `metric_id`, `value`, `threshold`, and `disposition`; it has exactly one result for every planned shortcut rule, metric/threshold equal that rule, finite values are required, and disposition is recomputed as `pass`, `fail`, or `underpowered`.

`approval_function_digest` equals the plan and recomputes the receipt's overall and component dispositions under its exact multiplicity rule. An approved QA receipt requires complete frozen-sample review, the overall bound and every mandatory stratum to pass, annotation completeness to pass for every admitted target, every required shortcut probe to pass, and valid adjudication. `reviewer_attestation_digests` contains the prospectively required qualified reviewers and a distinct adjudicator when disagreement occurs; every attestation binds this receipt's review subject and exact purposes. `disposition` is `approved`, `rejected`, or `blocked_external`. Missing conversion identity, eligible population, sampling design, completeness evidence, required clinical qualifications, adjudication, or shortcut evidence cannot be repaired by a zero observed-error count.

### `mmbu.phase1.custody_summary`

Required fields: `schema_id`, `schema_version`, `custody_id`, `source_digest`, `quarantine_authorization_digest`, `inventory_authorization_registry_digest`, `inventory_lock_digest`, `inventory_opening_receipt_digest`, `inventory_opening_receipt_registry_digest`, `inventory_started_at`, `inventory_ended_at`, `eligible_population_manifest_digest`, `qa_sampling_plan_digest`, `qa_authorization_registry_digest`, `qa_lock_digest`, `qa_opening_receipt_digest`, `qa_opening_receipt_registry_digest`, `qa_started_at`, `qa_ended_at`, `eligible_id_manifest_digest`, `exclusion_rule_digest`, `converter_digest`, `evaluator_fixture_digest`, `eligible_independent_unit_count`, `rights_receipt_digest`, `grouping_receipt_digest`, `qa_receipt_digest`, `disposition`, `limitations_digest`, `reviewer_attestation_digests`, `created_at`, and `record_digest`.

Custody has two non-circular protected stages. First, a container-level quarantine split is constructed without opening payload content: its record and parent manifests are the source-artifact manifest's exact artifact logical paths, its parent namespace is `artifact_path`, and its construction rule is the canonical path projection. Under the active quarantined source and quarantine-inspection authorization, a prospective inventory lock and protected-access opening permit named custody reviewers to decompress, inventory, and run the preregistered deterministic converter. That stage emits the closed lineage-bound `eligible_population_manifest`, converter digest, exclusion-rule digest, grouping evidence, and no model output. Second, the immutable `qa_sampling_plan` is created from that exact population after the inventory opening ends; a distinct QA lock binds the population and plan digests and exactly matches its seed/groups, and its protected opening binds both before QA review begins. QA reviewers inspect only the frozen sample or census and complete the QA receipt. The same source and quarantine authorization remain active and unexpired through both windows. Each named authorization registry is predecessor-complete and unchanged during its window; each named opening receipt is the active head under its corresponding lock throughout that window. `inventory_ended_at >= inventory_started_at`, the population and QA plan are created in that order after inventory end, `qa_started_at` is later than the plan, `qa_ended_at >= qa_started_at`, and `created_at >= qa_ended_at`. The QA receipt binds the same population and plan. `eligible_independent_unit_count` equals the population's eligible-parent count. Disposition is `passed`, `failed`, or `blocked_external`. Attestations are distinct, approved only when disposition is `passed`, and bind the exact summary subject. This closed record is the only source-admission information allowed to cross a sealed confirmation boundary; it contains no IDs, labels, frequencies, per-record outcomes, images, annotations, examples, or reviewer-disagreement detail. Any count-based feasibility choice is a separate planned decision whose sole content input is this summary's lineage artifact.

Required fields: `schema_id`, `schema_version`, `reproducibility_id`, `declared_level`, `source_state_digest`, `contract_manifest_digest`, `experiment_digest`, `prospective_lock_digest`, `opening_receipt_digest`, `opening_receipt_registry_digest`, `operator_id`, `started_at`, `ended_at`, `terminal_status`, `command`, `command_digest`, `working_directory`, `locale`, `timezone`, `filesystem`, `environment_variables`, `environment_artifact_digests`, `os_kernel`, `python`, `container_digest`, `hardware`, `frameworks`, `effective_numeric_settings`, `distributed_settings`, `seed_namespaces`, `rng_state_artifact_digests`, `worker_sampler_order`, `cache_network_policy`, `input_digests`, `output_digests`, `log_digests`, `exit_code`, `tolerances`, `compared_run_digest`, `observed_differences`, `reproduction_status`, `reproduction_limitation`, `created_at`, and `record_digest`.

This is an observed execution-payload record created before the reproducibility record that later binds it through `output_digests`; it never contains a reproducibility or run digest. `condition_digest` covers the exact model, processor, inputs, batch/sequence/image geometry, numeric settings, and warmup/measurement policy. `device_ids` is a unique ordered array of allocated GPU UUIDs or the singleton string `cpu`; public hardware specifications and scheduler requests cannot substitute for observed allocation.

## `mmbu.phase1.forward_backward`

Required fields: `schema_id`, `schema_version`, `probe_id`, `source_state_digest`, `experiment_digest`, `command_digest`, `model_digest`, `processor_digest`, `batch_digest`, `label_mask_digest`, `declared_trainable_patterns`, `parameter_inventory_digest`, `effective_settings_digest`, `loss`, `gradient_modules`, `optimizer_step`, `accumulation_comparison`, `output_digests`, `terminal_status`, `terminal_stage`, `started_at`, `ended_at`, `limitations`, `record_digest`.

This is also an execution payload and therefore never points to the later reproducibility or finalized run records. `declared_trainable_patterns` is a nonempty unique UTF-8-sorted array. `terminal_stage` is one of `initialization`, `preprocess`, `forward`, `loss`, `backward`, `optimizer`, or `completed` in that order; success requires `completed`, while a non-success records the last stage begun. `parameter_inventory_digest`, `batch_digest`, and `label_mask_digest` are strings on success. On non-success each may be null iff that artifact was not yet created, but any observed digest is retained; reaching `forward` or later requires both batch and label-mask digests, and reaching `backward` or later requires the parameter-inventory digest. `gradient_modules` is a UTF-8-module-name-sorted array of closed objects containing exactly `module_name`, `declared_trainable`, `parameter_count`, `gradient_parameter_count`, `finite_gradient_count`, `nonfinite_gradient_count`, `gradient_norm`, and `updated_parameter_count`; counts are nonnegative integers, the norm is finite or null exactly when no gradient exists, undeclared modules require zero gradient and update counts, and every declared trainable pattern must match at least one inventoried module when the inventory exists.

The nested objects are closed:

| Object | Exact fields and rules |
|---|---|
| `loss` | `framework_loss`, `manual_shifted_ce`, `absolute_difference`, `allowed_difference`, `target_token_count`, `ignored_token_count`, `finite`; on success numeric values are finite, target count is positive, ignored count is nonnegative, `finite` is literal true, and the observed difference cannot exceed a nonnegative tolerance fixed in `effective_settings_digest` before execution. | `optimizer_step` | `optimizer_id`, `learning_rate`, `pre_step_parameter_digest`, `post_step_parameter_digest`, `changed_parameter_count`, `step_succeeded`; on an attempted successful step, optimizer ID and pre-step digest are nonempty, learning rate is finite and positive, pre/post digests differ, at least one declared-trainable parameter changes, and `step_succeeded` is true while undeclared parameters remain byte-identical. ## `mmbu.phase1.example_manifest`

`contract_digest` resolves to one valid `mmbu.phase1.prompt_schema_contract`; `purpose` is the exact experiment purpose. `population_id` is a nonempty opaque identifier. `rows` is a nonempty ordered array of closed objects containing exactly `example_id`, `independent_unit_id`, `task_family`, `input_digest`, `requested_context_fields`, `task_weight`, `image_width`, `image_height`, `task_target_digest`, `context_target_digest`, `box_policy`, and `target_boxes_digest`. Example IDs and independent-unit IDs are nonempty and unique; their array order is the frozen evaluator order. `task_family` is `classification`, `counting`, `detection`, or `open_generation`. `input_digest` and `task_target_digest` are non-null digests. `requested_context_fields` is a duplicate-free ordered subset of the bound prompt contract's field registry; `context_target_digest` is non-null exactly when that array is nonempty. `task_weight` is a finite positive JSON number frozen before output opens.

For `detection`, `image_width` and `image_height` are positive integers, `box_policy` is `single`, `all_targets`, or `any_one`, and `target_boxes_digest` resolves to a nonempty immutable ordered array. ## Evaluation layers

All layer records require `schema_id`, `schema_version`, `record_id`, `example_id`, `example_manifest_digest`, `contract_digest`, `created_at`, and `record_digest`. `example_manifest_digest` resolves to one valid `mmbu.phase1.example_manifest`; `example_id` names exactly one row in it; and `contract_digest` equals that manifest's contract digest. Within one execution-output manifest, each layer schema has exactly one record for every example ID and no other example ID.

- `mmbu.phase1.raw_output` additionally requires `request_digest`, `input_digest`, `token_ids`, `decoded_text`, `finish_reason`, `effective_generation_settings`, `timing`, and `runtime_status`. `runtime_status` is `succeeded`, `load_failed`, `preprocess_failed`, `timeout`, `oom`, or `generation_failed`. `token_ids` is a nonnegative-integer array and `decoded_text` a string on success. On failure each is either the exact partial value produced before failure or null iff no such value exists; neither may be fabricated. `finish_reason` is a string on success and a string or null on failure. Generation settings is a closed object with `decoding_method`, `max_new_tokens`, `temperature`, `top_p`, `top_k`, `do_sample`, `num_beams`, `stop_token_ids`, `seed`, and `cache_enabled`; inapplicable sampling scalars are explicit null. Timing is a closed object with `started_at`, `ended_at`, and nonnegative `latency_ms`.
- `mmbu.phase1.parsed_output` additionally requires `raw_digest`, `parser_digest`, `parse_status`, and `parsed_value`. `parse_status` is `parsed`, `invalid_json`, `duplicate_key`, `nonfinite`, `multiple_objects`, `unknown_key`, `missing_required`, or `not_run`; `parsed_value` is a closed contract-governed object only for `parsed`, otherwise null.
- `mmbu.phase1.validated_output` additionally requires `raw_digest`, `parsed_digest`, `validator_digest`, `validation_status`, `requested_context_fields`, `geometry_status`, and `validated_value`. `validation_status` is `valid`, `invalid_schema`, `invalid_value`, `invalid_geometry`, or `not_run`; `geometry_status` is `valid`, `invalid`, `not_applicable`, or `not_run`; requested fields are a unique ordered subset allowed by the bound contract; `validated_value` is non-null only for `valid`.
- `mmbu.phase1.judged_output` additionally requires `raw_digest`, `parsed_digest`, `validated_digest`, `judge_digest`, `judge_status`, `task_grade`, `context_grades`, and `terminal_outcome`. `judge_status` is `judged`, `judge_failed`, or `not_run`; `terminal_outcome` is `success`, `runtime_failure`, `parse_failure`, `validation_failure`, or `judge_failure`. `task_grade` is a finite number in `[0,1]` and `context_grades` a closed map over the requested fields only when judged; otherwise both are null.

Legal status flow is deterministic: any raw `runtime_status` other than `succeeded` forces parse, validation, and judge statuses `not_run` and terminal outcome `runtime_failure`. A successful raw record requires a parse attempt; `parsed` requires a non-`not_run` validation attempt, while every other parse status forces validation/judge `not_run` and `parse_failure`. Validation `valid` requires judge `judged` or `judge_failed`; any other non-`not_run` validation status forces judge `not_run` and `validation_failure`. Judge `judged` maps to `success`; `judge_failed` maps to `judge_failure`. No layer rewrites its parent. A changed parent creates a new descendant digest.

Official task/context field names are not frozen here. They live in the bound prompt/schema contract and requested-field subset for the relevant `contract_status`.

## `mmbu.phase1.execution_output_manifest`

Required fields: `schema_id`, `schema_version`, `output_manifest_id`, `experiment_digest`, `example_manifest_digest`, `contract_digest`, `entries`, `created_at`, and `record_digest`.

`experiment_digest` resolves to the exact consumed experiment. `example_manifest_digest` resolves to the experiment's governing `mmbu.phase1.example_manifest`, and `contract_digest` equals that manifest's prompt/schema contract. `entries` is a nonempty array sorted by UTF-8 path bytes. Each entry is a closed object with exactly `path`, `bytes`, `sha256`, `media_type`, `schema_id`, `schema_version`, `record_digest`, `role`, and `example_id`. Paths obey the common normalized-path rules, are unique under exact bytes, Unicode normalization, and case folding, and resolve to regular non-symlink, non-hard-link files. Byte counts and hashes cover raw file bytes. `schema_id`, `schema_version`, and `record_digest` are non-null for schema-governed records and all validate against those exact bytes; they are all null for raw logs. `role` is `raw_output`, `parsed_output`, `validated_output`, `judged_output`, `failure`, or `log`. `example_id` is non-null only for the four per-example layer roles and equals the record's example ID; it is null for failures and logs.

The set of entry `sha256` values is exactly the bound reproducibility record's `output_digests`: no missing, duplicate, or extra digest is legal. For each example-manifest row, the entries contain exactly one record of each per-example layer role, with schema IDs `mmbu.phase1.raw_output`, `mmbu.phase1.parsed_output`, `mmbu.phase1.validated_output`, and `mmbu.phase1.judged_output`; the four example-ID sets each equal the complete example-manifest ID set. Their parent digests and legal statuses validate transitively. Aggregate `mmbu.phase1.task_change_summary` and `mmbu.phase1.geometry_summary` records are created only after the referenced condition manifests exist, obey `EVALUATOR_MECHANICS.md`, and enter the later evidence manifest; they cannot enter a condition manifest that they digest. A task-change summary additionally resolves one valid pre-output `mmbu.phase1.paired_condition_contract` plus the two finalized runs/reproducibility records and rejects any matched-condition drift.

An execution-output manifest never lists itself, an evidence manifest, source state, reproducibility record, finalized run, claims, requirement trace, or phase decision. Those later records may bind its `record_digest`. An opaque digest, a complete file list with an incomplete layer population, or set equality against a different experiment/example manifest is invalid.

## `mmbu.phase1.evidence_manifest`

Required fields: `schema_id`, `schema_version`, `bundle_id`, `members`, and `created_at`. It has no `record_digest` field and never contains itself.

Each member has exactly `path`, `bytes`, `sha256`, `media_type`, `schema_id`, and `schema_version`; the last two are both null for raw logs/prose or both non-null. Members are sorted by UTF-8 path bytes and cover every other bundle member exactly once. Only regular files are allowed. The externally retained bundle-root digest is SHA-256 of the RFC 8785 canonical manifest bytes.

## `mmbu.phase1.source_state`

Required fields: `schema_id`, `schema_version`, `commit_sha`, `dirty`, `patch_sha256`, `inventory`, `created_at`, and `record_digest`.

`patch_sha256` is null exactly when `dirty=false`; otherwise it covers a canonical binary patch that includes staged and unstaged tracked changes plus an explicit untracked-file inventory/content digest. Inventory members have exact path, bytes, SHA-256, and class (`source`, `test`, `config`, `contract`, or `lock`), sorted by path. It must cover every Phase 1 source, test, immutable implementation configuration, binding contract, and lock file. Here `config` means immutable implementation configuration and explicitly excludes the mutable execution-state authorities `config/phase1/current-status.json`, `config/phase1/authorization-registry.json`, and `config/phase1/opening-receipt-registry.json`. Those files are covered by the evidence manifest and are bound separately by status evidence, the experiment's authorization-registry digest, and the reproducibility record's pre-run opening-receipt-registry digest. Excluding them from `source_state` prevents state/provenance hash cycles; omitting any immutable implementation configuration remains invalid.

## Claims, trace, and decision

`mmbu.phase1.claims` requires `schema_id`, `schema_version`, `source_state_digest`, `claims`, `created_at`, and `record_digest`. The input claim set has exactly 22 members: P1-00 through P1-16, P1-17a, P1-17b, and P1-18 through P1-20. P1-21 is excluded because it is the derived decision output. Each input ID appears exactly once with `requirement_id`, claim `status`, `code_paths`, `test_ids`, `evidence_paths`, `evidence_digests`, and `limitations`. A `verified` row requires nonempty code/test/evidence references unless the binding row is document-only and explicitly names its document verifier.

`mmbu.phase1.requirement_trace` requires `schema_id`, `schema_version`, `source_state_digest`, `claims_digest`, `rows`, `created_at`, and `record_digest`. It has exactly one row for each of the same 22 input IDs, mapping stable behavior names to exact tests and evidence. Missing, duplicate, unknown, extra, or P1-21 input rows fail.

`mmbu.phase1.phase_decision` requires `schema_id`, `schema_version`, `claims_digest`, `trace_digest`, `decision`, `rejection_predicates`, `derived_at`, and `record_digest`. It must not contain P1-21 as an input. The standalone validator derives the decision exactly as `ACCEPTANCE.md` specifies and compares it with `decision`; this validated decision record is the evidence/output for P1-21. Claims, trace, and decision contain no bundle-root field. The manifest is computed last, covers all three records, and its root is retained outside the bundle, eliminating self-reference. A mismatch, self-reference, unknown status, invalid completed evidence manifest/root, or verified row with missing bound evidence rejects.

## Minimal chronology examples

Valid: lock `L` at `10:00Z`; opening receipt at `10:01Z`; execution consumes the immutable experiment bound to `L`; its reproducibility record binds that experiment, `L`, the receipt, and payloads; the finalized run then binds both experiment and reproducibility digests; decision code and thresholds match `L`.

Invalid: output exists at `09:59Z`; lock is created at `10:00Z`; an opening receipt later points to the lock. The result remains exploratory. Also invalid: a pre-opening amendment changes the seed but omits `supersedes_digest`, or a post-opening amendment claims to preserve confirmation.

## Minimal cross-record examples

Valid: a quarantined source with empty purposes receives immutable rights, grouping, and QA receipts; a successor source record becomes `approved` for `engineering`; an engineering split references that successor; a purpose authorization allows only `engineering`; lineage intersection remains `engineering`; and the experiment consumes those exact digests.

Invalid: a source is `candidate` but lists `train`; a split calls itself `train` while its source permits only `engineering`; a purpose authorization infers `adaptive_dev` from legacy `development`; or a migration omits the legacy input digest. Each fails before execution.

Valid: `current-status.json` records the public MOCS specification as one measured public fact while the account allocation is a separate `unknown` fact with null value and a limitation. Invalid: copying the public GPU count into the account-allocation value.

Valid: a `brief_snapshot` prompt contract binds exact published-source, prompt, output-schema, parser, validator, judge, and inference digests, while preserving the provisional status. Invalid: changing a requested context field, parser, or inference setting without a successor contract, or relabeling the same bytes `organizer_confirmed` without a written-answer digest.

Executable JSON Schemas or equivalently strict typed validators must implement this contract and its cross-record graph/chronology rules. Self-authored fixtures alone are insufficient: every invariant above needs a positive and adversarial negative test.
