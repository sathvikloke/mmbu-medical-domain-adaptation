## Findings that change the next experiment

Qwen3.5's default thinking prompt did not exactly prefix-match a plain-JSON assistant target. Explicit `enable_thinking=False` resolved the tested mismatch. Validate every example's actual assistant boundary and align the eventual inference policy with the confirmed contract; copying a fixed prompt length is unsafe. [Processor details](../../outputs/mmbu-precompute/docs/processor-compatibility.md).

All three tested native processing paths lost or mis-scaled direct uint16 intensity information. Use a reviewed, explicit display mapping with recorded provenance for source-native16 imagery. Processor acceptance alone is not a valid presentation policy. [Presentation details](../../outputs/mmbu-precompute/docs/supervision-and-presentation.md).

Equal averaging of unequal microbatch mean losses changed the intended objective in the synthetic probe. Normalize by the total shifted assistant-target token count over the accumulation window and test the actual trainer integration once available. [Loss details](../../outputs/mmbu-precompute/docs/causal-loss.md).

The native B2 objective test confirmed the exact global weighted numerator/denominator under fixed singleton
microbatches, but two prospective concatenated-versus-partitioned tests failed when batch shape changed. The safe
reference condition is therefore singleton accumulation with complete-cycle stopping until a separately frozen
shape-bucketed successor passes. [Native objective trace](B2_DUAL_OBJECTIVE_PREFLIGHT_TRACE.md).

ROCO/PMC-VQA article overlap, caption-derived targets, visible overlays, and ambiguous figure lineage require deliberate review. More images do not resolve those issues. Exact/perceptual duplicate tools provide review evidence, not a proof of independence or no leakage. [Source expansion](../../outputs/mmbu-precompute/docs/source-expansion.md), [ROCO sample](../../outputs/mmbu-precompute/docs/roco-sample.md).

## Reading reviews and failures correctly

Historical independent reviews were conducted by **separate AI agents**, sometimes with independently written probes. They are not human peer review, external scientific validation, legal clearance, or biomedical adjudication. Review reports are scoped to named files, hashes, commands, and counterexamples; a `PASS` does not extend beyond that scope.

Files containing `red`, `initial`, `failure`, or `counterexample` preserve meaningful development failures. They are intentionally retained. Later repaired reports and the final suite receipt establish the final software state; old failing logs neither invalidate a verified repair nor disappear because a later run passed. Useful review entry points are the [CPU coverage audit](../../outputs/mmbu-precompute/evidence/cpu-coverage-audit.md), [processor review](../../outputs/mmbu-precompute/evidence/processor-independent-review.md), [source-processor review](../../outputs/mmbu-precompute/evidence/source-processor-independent-review.md), and [original plan review record](../../outputs/MMBU-audit-review-record.md).

## Verify or extend a result

Run `python3 tools/team.py verify-evidence` from the repository root for the supported saved-artifact checks, including the recorded publication transforms, then the relevant test or documented probe for a fresh execution. Restore the [release inputs](DATA_AND_MODELS.md) before a replay requiring real images or processor snapshots. Integrity verification checks recorded bytes; reproduction additionally checks behavior in your environment.

Save a new result with command, working directory, environment versions, code and input hashes, exit code, raw output, and interpretation. State what changed from the historical run. Never replace an old receipt with your rerun or carry the historic “277 passed” label onto a different untested environment.
