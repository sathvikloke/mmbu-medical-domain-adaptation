## Necessary, actionable work before closing this CPU phase

1. **Explicit task/context target serialization — assigned to the experiment-records worker.** Existing `data.py` checks annotation shapes and `contracts.py` parses generated task outputs, but `supervision.py` starts with already serialized token IDs. Add the small missing bridge under explicit local profiles: classification/count/multi-label/box targets, strict geometry, no fabricated rationale, round-trip checks and clearly local context-key policy. This prevents ad hoc serializers from silently changing target types/cardinality or rationale placement. It does not settle the official schema or approve model use.
2. **Conservative near-duplicate candidate triage — assigned to root.** `images.py` explicitly supports exact decoded representation only. The original plan requires screening alternate encodings/related images in addition to exact hashes and lineage. A bounded, non-learned candidate report over the present quarantine images, with synthetic re-encoding counterexamples, is useful now. Keep it separate from official inference. It must not automatically merge patients, delete samples, certify independence or claim to detect all crops/semantic duplicates.
3. **Complete already authorized source-image work and its actual checks — active.** During this audit the acquisition receipt recorded 24 selected ROCO training images, and `work/roco-quarantine/prepared/image-inspection.json` reported 24 decoded images with no exact decoded duplicates. The per-article rights report records 24 retrieved XML documents, 22 unique normalized-caption figure matches and two unresolved matches, with no model-use approvals. Finish preserving the acquisition/review outcomes, actual native processor behavior and any visible conversion failures. This is not a reason to acquire large additional corpora. The publication archive's whole-file checksum is not independently verified by selected range/member retrieval; keep that distinction.
4. **Finish integration/status reconciliation and one final verified portable artifact — root-owned.** The current README still emphasizes v0.2; `docs/cpu-completion-plan.md` has unchecked items despite implemented modules. The current ROCO registry entry still says version `2`, unresolved archive revision and no acquisition, while the new evidence identifies 2.0.1 and selected files. PMC-VQA's registry overlap text also predates the exact article intersections. Update current status/evidence pointers and exact versions without granting source approval. Run the final affected/full tests and clean-copy offline checks after code stops changing, and create new receipts/archives without altering historical v0.1/v0.2 evidence. Stale inventory is ordinary CPU work, not an external blocker.

The concrete gaps above have owners; no parallel duplicate implementation is needed. The synthetic loss check was also active at assignment and is now independently replayed below. These are completion tasks, not proof of scientific efficacy.
