Do not replay these cookies to test their privileges.

The manifest and verification logic should explain these limited intentional changes. Preserve source URLs, content hashes, byte counts, timestamps, and source-review decisions. ## Evidence and limitations

The source scan excluded `.venv`, `__pycache__`, `node_modules`, `.git`, the new staging repository, and this delivery-audit directory. It inspected 978 UTF-8 file/member instances totaling 138,497,024 decoded bytes, including text inside all six existing ZIP archives. The three output ZIPs have 67, 127, and 276 members; the BBBC image, mask, and metadata ZIPs have 404, 404, and 16 members. None of these six archives contains a nested ZIP. Only v0.3 duplicates the source-expansion cookie/signed-URL fields. Eight HTML source captures under `work/` were separately checked. Structured JSON traversal found session fields missed by simple string patterns; values were never printed in the report.

Existing BBBC/ROCO acquisition receipts, including the recorded ROCO first-attempt failure, were checked for credential/session keys without finding any. Binary image pixels and PDF internals were not newly content-audited; source-document text and provenance reports were inspected. No authentication files outside the project were accessed. This initial report does not certify the final staged repository or release bytes; they require a final inventory/redaction check after packaging.
